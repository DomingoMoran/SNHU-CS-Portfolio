# CS210 CornerGrocer Project Reflection

## Project Summary

For this project, I created a C++ program called CornerGrocer. The program reads a text file containing grocery items and counts how many times each item appears. It allows users to search for an item, display the frequency of all items, and view a histogram of the results. The goal was to make grocery data easier to organize and understand.

## What I Did Well

I think I did a good job getting the program to run and making sure the menu options worked as expected. I also worked through problems with the input file path and build errors in Visual Studio. These issues took some troubleshooting, but I kept working until I got the program running. This taught me to be patient and test my code instead of giving up when something does not work right away.

## Areas for Improvement

One area I could improve is error handling. For example, I could make the program explain what went wrong if the input file cannot be found. I could also improve input validation so invalid menu choices do not cause problems. These changes would make the program more reliable and easier for users to work with.

## Challenges and How I Overcame Them

One of the hardest parts was getting the program to find the input file and fixing build errors in Visual Studio. I checked the file location and working directory and tested the program after making changes. I learned that small details, like a file path, can prevent a program from working correctly. In future projects, I can use course materials, C++ documentation, debugging tools, and instructor feedback to help solve similar problems.

## Transferable Skills

This project helped me practice C++, file handling, organizing data, using functions, and debugging. These skills will be useful in future programming courses because I will need to write code, find errors, and test programs. I also learned that understanding why an error happens is important instead of only trying random fixes.

## Maintainability, Readability, and Adaptability

I worked to keep the program organized by separating its different tasks and using functions to make the code easier to follow. Clear names and an organized menu also help make the program easier to understand. Keeping the code organized makes it easier to fix problems or add features in the future.
